### 2026-09-20 10:26:12 HKT — first high-risk structural checks

- `behavior/schedule.v` is not a direct record translation. Official Prosa 0.6 bundles `State`, `Core`, `scheduled_on`, `supply_on`, `service_on`, `service_on_le_supply_on`, and `service_on_implies_scheduled_on`. Lean externalizes `State`, adds explicit `Fintype`/`DecidableEq`, removes `supply_on` and `service_on`, makes aggregate `service_in` primitive, and replaces the two official invariants with one weaker aggregate implication. This is a **HIGH structural mismatch**, not a harmless field renaming.
- Consequently official `supply_in` and the official sum-derived `service_in` have no Lean counterpart. Lean's same-named `ProcessorState.service_in` corresponds to neither declaration 1:1; it is a different abstraction boundary.
- `behavior/service.v` has one pinned-source declaration absent from Lean: `receives_service_at`. The other service definitions have same-name candidates, but all service-based definitions inherit the `ProcessorState.service_in` mismatch.
- Official `completes_at` contains the zero-time disjunct `(t == 0)`; Lean omits it. The previously kernel-checked `t = 0`, zero-cost counterexample confirms this as a genuine **HIGH semantic statement mismatch**.
- `behavior/arrival_sequence.v` has a clear pinned-source omission: `arrivals_between_P`. The other 13 declarations have direct structural candidates (`seq` represented by `List`, boolean predicates by `Prop` where applicable).
- `behavior/job.v` has all five counterparts, but `JobType := eqType` became `JobType := Type`; equality evidence is reconstructed via `[DecidableEq Job]` at use sites. This is a representation reformulation, not a missing declaration.
- `util/sum.v` is substantially from the wrong source inventory. Pinned Prosa 0.6 has 27 declaration headers; Lean has 16 source-level declarations, only seven exact same-name matches. Lean-only `sum_seq_gt0P`, `sum_diff`, `sum_pred_diff`, `sum_seq_diff`, `sum_notin_rem_eqn`, `sum_majorant_eqn`, and `sum0` are not declarations in pinned `util/sum.v`; two additional Lean declarations are explicit helpers. Conversely twenty pinned declarations are absent from this Lean file.
- The processor implementations confirm downstream impact: official `Spin` defines `spin_supply_on` and per-core `spin_service_on`; Lean replaces both with aggregate `spin_service_in`. The ideal and multiprocessor translations make the same abstraction change. These are downstream manifestations of the generic `ProcessorState` mismatch.

No production Lean file was modified, and no semantic proof was started in this audit.

### 2026-09-20 10:34:18 HKT — cross-file matching and curated declaration audit

#### What is and is not a 1:1 match

The frozen Lean repository is commit `2b8d0b99e46103940c3d1b2c1b3943e55d4404d8`. The source baseline remains official Prosa 0.6 commit `414e66760333eaa4ef78c685bcf53291c527a548`. The installed opam source copy does not retain its `.git` directory, so the commit identity is the pinned package provenance already recorded by the validation work rather than a new `git rev-parse` result.

The matching procedure now distinguishes four increasingly weak forms of evidence:

1. same normalized file path, same declaration name, and compatible declaration role;
2. same name in a demonstrably moved/split Prosa 0.6 file;
3. renamed or representation-level reformulation, checked by parameters, result type, fields, and defining expression;
4. name-only candidates, which are **not** accepted as 1:1 when the name occurs in several source files or the signatures have not been disambiguated.

Across the complete public modern inventory, 535 declaration occurrences have an exact same-file/same-name candidate. A further 137 occurrences can be paired by name across files, giving an upper bound of 672 same-name pairs. Hence:

- 1415 of 2087 public Rocq declaration occurrences have no same-name Lean declaration anywhere in the modern frozen tree;
- 136 of 808 public Lean declarations remain after maximal global same-name pairing;
- independently of names, the declaration cardinalities imply that **at least 1279 official public Rocq declarations cannot have a 1:1 Lean declaration** (`2087 - 808`), even under an unrealistically perfect pairing;
- this lower bound is conservative: Lean helpers and declarations translated from an older source consume part of the 808 Lean declarations.

These numbers measure declaration coverage, not semantic correctness. Local section declarations are included when they create a Rocq constant; kernel-generated constructors, recursors, and projections are not counted as ordinary extras.

#### What likely needs production modification, and what does not

Clear translation changes would be required for faithful Prosa 0.6 coverage of:

- the generic `ProcessorState` supply/per-core-service interface and all affected concrete processor instances;
- `completes_at`'s zero-time case;
- missing core declarations `receives_service_at`, `TaskMinCost`, and the minimum-cost validity family;
- any v0.6 theorem family claimed as fully translated but absent, notably the supply/service facts and large portions of `util/sum`, `util/bigcat`, `util/list`, and `analysis/facts/model/rbf`.

The following are representation differences and should **not** be called translation failures without semantic validation:

- `JobType : eqType` ↔ Lean carrier `Type` plus `DecidableEq` evidence;
- MathComp `finType` ↔ Lean `Fintype + DecidableEq`;
- `seq` ↔ `List`, MathComp boolean predicates ↔ Lean `Bool` or `Prop` as appropriate;
- source `set` ↔ Lean `SeqSet` plus explicit coercion/membership/equality instances;
- `ideal_is_idle` ↔ `is_idle`;
- file moves and splits whose declaration types still align.
