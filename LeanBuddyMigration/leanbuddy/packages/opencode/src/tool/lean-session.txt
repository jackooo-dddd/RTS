Interactive Lean proof states for incremental tactic proving, backed by Pantograph.

A session holds the live goal state of one theorem or one assigned proof_region of the current staged file. Goals always come from the file as it is: its imports, namespaces, `open`s, earlier `have`s and binders. Other proof regions are treated as `sorry` while the state is built, so an unfinished or broken sibling region does not block this one.

Operations:
- "open": open a session for `file`/`theorem`. A lemma worker with an active assignment opens at that proof_region (theorem scope is refused); otherwise pass `scope: "theorem"` for the theorem's proof start or `admit_id` for a region. Optional `expected_goal` is compared with the live goal by definitional equality (not text); a mismatch reports `session_state_desync` and blocks tactics.
- "step": run one tactic (or a short tactic block) on the session's first goal. Returns the new goals or Lean's error message. A failed tactic leaves the state unchanged.
- "goal": show the current goals with hypotheses.
- "inspect": read-only check whether `left_expression` and `right_expression` are definitionally equal in the current context (`rfl`), plus the types of up to eight `symbols`. Use it when an escalation depends on hidden arguments, instances or unfolding; `convertible` favours a local bridge, it does not prove anything by itself.
- "snapshot": remember the current state; "undo" with `snapshot_id` returns to it.
- "close": end the session. "status": session summary.

Rules:
- The source file stays the authority: "No goals" in a session is not a certificate. Write the working tactics into the file and check it with `lean_check` or `checkpoint`.
- When the staged file changes, the next operation re-opens from the file and replays the successful tactics; if that replay fails you get `session_state_desync`.
- `step` rejects `sorry`, `admit`, `native_decide` and the other forbidden tokens.
- Prefer small steps; take snapshots after meaningful progress and use undo instead of replaying long scripts.
- `backend_error` is a tool failure (the Lean process restarted or timed out), not a proof result; retry the operation.

Feedback classification:
- proof_progress: the tactic succeeded (goals changed or closed)
- environment_problem: unknown identifier/constant, missing instance, or a tactic that failed on the goal
- syntax_or_engine_problem: parse error or unknown tactic
